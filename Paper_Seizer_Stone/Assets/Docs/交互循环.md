# 基础实现

> 本阶段实现基础牌、八张特殊商品牌、揭牌与获胜能力、玻璃变形、商店及摊牌烧牌。床单、论外牌与标签暂不实现。入口为 `Assets/Scenes/BasicBattle.unity`，三套可编辑 Panel 共用转场流程，详见《基础战斗架构.md》。

### 1. 场景构建

场景及外观使用已保存的可编辑资源，不在运行时程序化搭建。BasicBattle 场景包含 BattleTable、BattleCameraRig、BattleHUD 和 VirtualProjectionRoom 的预制体实例；桌子、卡槽、牌堆、左轮、子弹、筹码和对手使用可单独替换的道具预制体。卡牌预制体保存完整牌体、牌面、卡背、半透明底牌、文字与碰撞体。子弹与筹码预制体保存刚体和碰撞体，对应区域保存空气墙、地面、上盖及落点。运行时只实例化已有的卡牌和道具预制体，推进战斗状态及播放动画。

房间使用 `Assets/Game/Prefabs/Environment/VirtualProjectionRoom.prefab`，将固定参考图片投到地板、后墙、左右墙和顶面组成的单一网格。可用背景包括带蓝绿发光点的 `Virtual Projection Timber Cabin.png` 和此前生成的 `Virtual Projection Timber Cabin No Glow.png`；本轮保留用户当前贴图选择，以场景投影组件的 `projectionTexture` 为准。无荧光版保留构图和归一化墙角，实际尺寸为 `1774×887`，不是 4K；该版本使用 NPOT None、无压缩、Max Size `4096`、Mip Maps、Trilinear、Aniso 16、Clamp，局部大幅放大的细节仍受实际像素数量限制。本轮没有更换图片、模型、Transform 或相机配置。

模型为 `Assets/Game/art/model/VirtualProjectionRoom.obj`，材质为 `Assets/Game/art/matrial/shader/VirtualProjection.mat`，使用 `Assets/Game/art/shader/Toon/VirtualProjectionToon.shadergraph`。选中 `VirtualProjectionRoom` 根节点，通过组件的 `brightness`、`tint` 调整体明暗与颜色；贴图和亮度以组件传入的 MaterialPropertyBlock 为准，现有值不因本轮受光支持而重置。材质的 `_BackgroundSaturation`、`_HighlightCompression` 及原色阶继续可调；新增 `_SceneLightingStrength`（默认 `0.65`）混合主光和附加灯漫反射，`_SceneLightFloor`（默认 `0.4`）控制受光保底，两者范围均为 `0～1` 且不被组件覆盖。受光强度为 `0` 时保留纯图片表现。房间没有碰撞体，使用 Ignore Raycast 层，不参与布局转场；RoomShell 接收阴影但不投射阴影。具体配置见《基础战斗架构.md》的“虚拟投影房间”。

游戏处于3D场景内，以交互区域以桌面2D区域为主的伪2D游戏。

桌子两侧分别为玩家第一视角和敌手。

桌面包含两把左轮，子弹（右手侧），回合计数器，筹码（左手侧），卡牌区域（8个长方格，场景中心侧），手牌区，靠近相机下方区域。双方的抽牌堆，弃牌堆（左手侧）

玩家场上的己方暗牌半透明显示牌面，使玩家能直接辨认自己的底牌。半透明显示不视为公开或翻牌，不触发揭牌效果，也不向电脑提供暗牌内容；对方未公开的牌仍只显示卡背。

装弹数量通过桌面的实体子弹表达，不额外显示“4/6”等数字。子弹落在各自的有限区域内，自然碰撞散落，不再使用整齐的两排弹巢占位。筹码也采用物理落桌，区域边界保持不可见。

牌库使用略微凌乱的卡背层，每层保存少量水平位移和旋转，数量变化时只增减可见层，不重新随机整体姿态。

卡牌、桌面及屏幕提示统一使用提供的 ResourceHanRoundedCN-Bold SDF 中文字体。屏幕界面保存为可编辑的 Canvas 与 TextMeshPro，屏幕上方显示回合阶段和双方得分，下方按阶段显示简短动态与操作提示；桌面保留中文短标签、牌库和弃牌数量及实体按钮。标题使用暖金色，我方与对手分别使用蓝色和赤褐色，等待中的按钮弱化显示。

操作的各个单位元素为3D物体，不同行为时，相机角度可能发生转换。

槽位、枪械、子弹、筹码、对手占位模型、桌面确认按钮、商店陈列与卡牌等不透明道具使用 `Assets/Game/art/matrial/Toon/` 下的独立材质副本，保留原始颜色与贴图。通用节点图为 `Assets/Game/art/shader/Toon/ToonSurface.shadergraph`，保留原材质、主光阴影、低频笔触、三段明暗、最低亮度、小面积高光和输出，并增加附加灯受光；双击节点图或选中对应材质即可调整。明暗阈值默认 `0.33`／`0.7`，分界柔化为 `0.035`，牌面笔触较弱以保留可读性。通用、桌面旧木与积分器图共用 `Assets/Game/art/shader/Toon/ToonAdditionalLights.hlsl`，额外漫反射和高光独立叠加，材质 `_AdditionalLightStrength` 默认 `1`、范围 `0～2`；已有材质数值保留。房间通过独立参数混合场景灯光。半透明 Ghost、枪口 Flash、发光 BurnEmbers 及 UI 文字继续使用原材质。

可直接调整场景 Point／Spot 的颜色、强度、范围、聚光角、阴影与 Cookie；附加灯按每物体列表采样，包含距离／聚光角衰减、实时阴影和 Cookie，Shader Graph 节点预览的附加灯贡献为零。当前目标是 URP `12.1.13` Forward 逐像素附加灯：High 每物体最多 `8` 盏并支持附加灯阴影，Balanced 最多 `2` 盏且无附加灯阴影，Performant 关闭附加灯；本轮未修改质量配置，也未增加 Vertex 或 Light Layers 模式。房间灯光的 Culling Mask 需包含 Ignore Raycast 层。具体资源与参数见《基础战斗架构.md》的受光说明。

当前 `BattleTable/TableSurface/table` 另使用 `Assets/Game/art/matrial/shader/Table_Wood_Painterly.mat` 与同目录的独立节点图，保留中性灰褐、少量灰绿和粗块笔触，以及细裂纹与白亮边的压制；主要细节参数为 `DetailMip=2.2`、`DetailSoftening=0.78`、`SourceRetention=0.08`，笔触密度／强度为 `18`／`0.06`。木材除主光和 Baked GI 环境补光外，现在也接收 Point／Spot 附加灯，`_AdditionalLightStrength` 控制其贡献。现有主光、环境光、材质已有数值、模型、UV、Transform 均未在本轮重置；未新增灯光、后处理或描边。配置入口见《基础战斗架构.md》的“桌面旧木材与灯光”。

本次继续使用 Unity `2021.3.32f1c1` 及 Shader Graph／URP `12.1.13`，没有升级依赖，按工作规范未编译、测试、资源验证、查日志、启动编辑器试玩或控制屏幕。



### 2. 相机控制

玩家相机在回合中不同阶段切换时，相机将在不同预设位置间较快平滑切换。

主相机保存在 BattleCameraRig 预制体内，操作、计分和射击三组机位的位置、旋转及转场时长由 `Assets/Game/Data/Cameras/BasicBattleCamera.asset` SO 管理。槽位、手牌、牌库、弃牌、举枪与拖拽平面仍使用可编辑的定位点，运行时读取其位置，不覆盖为代码内的固定坐标。

包含以下几个状态：

操作阶段：

俯视角看向场景桌面（最常见操作阶段）

垂直视角关注桌面 （结算阶段）

正看向对方（射击/被射击阶段）

不设置独立的对手观察或反应特写机位；正看向对方的视角仅用于射击与被射击阶段。

房间的 `ProjectionOrigin` 为独立固定参考点，不随主相机切换。OBJ 沿用此前按 Timber Cabin 后墙、侧墙墙脚与顶边匹配的五组共面大面；无荧光版保留相同构图，本地地板高度仍为 `y=-3`，前沿仍为 `z=-22`。本轮仅更换背景与调整表面风格和现有光照颜色，房间根节点、`RoomShell`、投影参考点和相机的全部 Transform、网格、相机 SO 均保留，投影视野仍为场景 26 度／预制体 53 度，采样区域仍为 `(0.18, 0.12, 0.625, 0.625)`。计分和射击视角超出图片的区域以暗色柔和补齐；单图在边缘和大幅机位变化时仍可能拉伸，也不承诺完全消除生成痕迹。按工作规范未运行 Unity 编译、测试或试玩。



### 3. 交互操作

游戏中的交互操作多以拖拽卡牌和点按等行为实现。

手牌区：手牌呈扇形排列。鼠标移入屏幕下方四分之一区域时，展开手牌间距；离开后收拢。拖拽过程中保持布局，避免目标移动。

出牌阶段：拖拽手牌置于场上槽位，敲击确认按钮确认操作。

作弊阶段：

- 左键拖拽一张合法卡牌（手牌中/场景上等，若合法则可以拖拽起来），松开后根据位置判断是否合法，若合法则进行本轮作弊操作。点确认按键跳过作弊。

- 点击抽牌堆，抽取一张卡牌。



### 4. 流程动画

游戏中的各项操作需要对应的反馈动画配置。项目中已配置有DOTWEEN，需要时可以使用。

动作结束后默认留白 0.15 秒，阶段与机位切换后留白 0.3 秒，胜利后停留 0.8 秒。时间在 BattleController 配置；双方作弊的并行动画作为一个整体留白，不拆成先后行动。

对手做的操作可以不用绑定动画，全部以平滑形式执行即可。

1. 准备阶段，首回合玩家抽 5 张、对手抽 4 张，后续双方各补 4 张；卡牌从抽牌堆一张张飞入双方手牌区（主要是飞入玩家手牌区域的演出）。筹码在战斗开始或绸缎获胜使奖池增加时从上方依次落桌，不在每回合重新投放；每回合双方装弹数重置为两发，并重新从各自的子弹落点投入。普通界面刷新保留已落定的实体位置。

2. 摆牌阶段，对手将若干张卡牌直接飞入摆在对方框内，玩家从手牌区拖放四张卡牌，使用 3.交互操作 出牌阶段交互动画。

3. 开牌阶段，从两种卡背颜色的尚未公开卡牌中各随机选择一张，先翻开玩家颜色的卡牌并结算揭牌效果，再翻开对手颜色的卡牌并结算揭牌效果，然后进入作弊阶段并冻结电脑可见快照。玩家完成操作或跳过后，只向该快照补充禁止操作的卡牌 ID，电脑依据“作弊开始时快照＋禁止内容”决策，不能读取玩家操作后的场面。规则层结算双方操作后，换位、换牌、抽牌和加弹在同一批演出中同时开始；作弊增加的子弹通过物理模拟落入对方区域。阶段结束后清空快照和禁止列表。第四次揭牌按同样的颜色优先级翻开所有剩余暗牌并结算揭牌效果，随后直接计分，不再作弊。
4. 结算阶段，相机切至垂直桌面的计分视角，四组对位依次强调卡牌并显示累计得分。基础规则胜者得 2 分，负者得 0 分，平局双方各得 1 分。锤子、大木箱改变对位结果，花剪刀落败得 1 分；绸缎获胜投放两枚新筹码，火药纸获胜投放己方一发子弹，最多六发。揭牌钳子减少对手一发子弹、最低一发；揭牌叉子抽牌。对应卡牌脉冲强调，动态提示说明能力结果。
5. 执行阶段，相机切至正对对手的射击视角，胜方举枪执行一次射击；敌方需要开枪时，举枪瞄准后枪身微微、不规则颤抖，短暂停顿后开枪。同分时双方结果先统一判定，再同时播放双枪演出，不因一方倒下取消另一方射击。当前使用占位枪械与反馈，可配置音效资源。
6. 若双方存活，相机回到桌面，双方场上牌移入各自弃牌堆，保留手牌并移除一枚筹码；筹码为零时继续战斗。随后自动准备下一回合。玩家失败时结束冒险；玩家胜利时将剩余奖池加入钱包，开始战后转场。

### 5. 战后商店、烧牌与下一场

1. 胜利反馈停留后，相机回到桌面，战斗卡牌、槽位、枪械、子弹、筹码、对手及战斗 HUD 分批飞出。先固定物理实体，再逐件沿「当前位置相对桌心的水平外延方向＋向上＋小幅随机偏移」飞离，HUD 在屏幕内移动。入场从相应外上方位置飞回布局。
2. 商店使用保存的 ShopTable Panel，商品、价格和牌组预览分别飞入，屏幕 UI 在原位用 0.3 秒淡入淡出；钱包筹码自然落桌。显示可用余额、玩家生命及下一名敌人。基础牌与特殊牌共同抽取三件商品，默认至少一张特殊牌，鼠标悬停显示能力和价格，点击购买后售罄。
3. 点击「烧牌整备」，先让商店陈列离场，再进入 BurnTable Panel，将整个持有牌组摊开。点选具体实体牌后抬起高亮，侧栏展示牌名、能力与费用。默认支付三筹码，最少保留五张牌；余额不足或达到下限时禁用确认并提示原因。可以按 Esc 或「返回商店」取消。
4. 每次合法交易先原子修改冒险数据，再锁定输入播放演出。购买时商品飞入牌组、等额筹码飞向支付出口；烧牌时选中牌飞入火盆并旋转缩小消失，同时支付等额实体筹码。烧牌完成回到原商店，库存和售罄状态保留，余额及牌组刷新。
5. 点击「下一场战斗」，商店组件离场、战斗组件入场。玩家牌组、剩余生命和钱包保留，奖池重新按战斗配置摆放。敌人按配置列表轮换，生命、牌组和外观来自对应 SO。

三套布局统一由 TablePanel 管理内容显隐和转场：世界物件使用 TableFlyGroup，商店 HUD 使用 TableFadeGroup，其余 HUD 保留 TableFlyGroup；模板保存在预制体中，桌体、灯光和相机作为共同环境。运行时仅实例化已保存的卡牌和筹码预制体，不搭建整套桌面。
