# 基础实现

> 本阶段仅实现基础石头、剪刀、布。非基础牌、标签及其触发效果暂不实现；下面的揭牌顺序已保留，但当前揭牌只改变公开状态。独立入口为 `Assets/Scenes/BasicBattle.unity`，详见《基础战斗架构.md》。

### 1. 场景构建

场景及外观使用已保存的可编辑资源，不在运行时程序化搭建。BasicBattle 场景包含 BattleTable、BattleCameraRig、BattleHUD 的预制体实例；桌子、卡槽、牌堆、左轮、子弹、筹码和对手使用可单独替换的道具预制体。卡牌预制体保存完整牌体、牌面、卡背、半透明底牌、文字与碰撞体。运行时只实例化已有的卡牌和筹码预制体，推进战斗状态及播放动画。

游戏处于3D场景内，以交互区域以桌面2D区域为主的伪2D游戏。

桌子两侧分别为玩家第一视角和敌手。

桌面包含两把左轮，子弹（右手侧），回合计数器，筹码（左手侧），卡牌区域（8个长方格，场景中心侧），手牌区，靠近相机下方区域。双方的抽牌堆，弃牌堆（左手侧）

玩家场上的己方暗牌半透明显示牌面，使玩家能直接辨认自己的底牌。半透明显示不视为公开或翻牌，不触发揭牌效果，也不向电脑提供暗牌内容；对方未公开的牌仍只显示卡背。

装弹数量通过实体子弹及弹巢中的占位表达，不额外显示“4/6”等数字。

卡牌、桌面及屏幕提示统一使用提供的 ResourceHanRoundedCN-Bold SDF 中文字体。屏幕界面保存为可编辑的 Canvas 与 TextMeshPro，屏幕上方显示回合阶段和双方得分，下方按阶段显示简短动态与操作提示；桌面保留中文短标签、牌库和弃牌数量及实体按钮。标题使用暖金色，我方与对手分别使用蓝色和赤褐色，等待中的按钮弱化显示。

操作的各个单位元素为3D物体，不同行为时，相机角度可能发生转换。



### 2. 相机控制

玩家相机在回合中不同阶段切换时，相机将在不同预设位置间较快平滑切换。

相机与三个机位定位点均保存在 BattleCameraRig 预制体内，可在编辑器中直接移动、旋转和保存。槽位、手牌、牌库、弃牌、举枪与拖拽平面也使用可编辑的定位点，运行时读取其位置，不覆盖为代码内的固定坐标。

包含以下几个状态：

操作阶段：

俯视角看向场景桌面（最常见操作阶段）

垂直视角关注桌面 （结算阶段）

正看向对方（射击/被射击阶段）

不设置独立的对手观察或反应特写机位；正看向对方的视角仅用于射击与被射击阶段。



### 3. 交互操作

游戏中的交互操作多以拖拽卡牌和点按等行为实现。

手牌区：手牌呈扇形排列。鼠标移入屏幕下方四分之一区域时，展开手牌间距；离开后收拢。拖拽过程中保持布局，避免目标移动。

出牌阶段：拖拽手牌置于场上槽位，敲击确认按钮确认操作。

作弊阶段：

- 左键拖拽一张合法卡牌（手牌中/场景上等，若合法则可以拖拽起来），松开后根据位置判断是否合法，若合法则进行本轮作弊操作。点确认按键跳过作弊。

- 点击抽牌堆，抽取一张卡牌。



### 4. 流程动画

游戏中的各项操作需要对应的反馈动画配置。项目中已配置有DOTWEEN，需要时可以使用。

对手做的操作可以不用绑定动画，全部以平滑形式执行即可。

1. 准备阶段，卡牌从抽牌堆一张张飞入双方手牌区（主要是飞入玩家手牌区域的演出）。筹码只在战斗开始时摆放，不在每回合重新生成；每回合双方装弹数重置为两发。

2. 摆牌阶段，对手将若干张卡牌直接飞入摆在对方框内，玩家从手牌区拖放四张卡牌，使用 3.交互操作 出牌阶段交互动画。

3. 开牌阶段，从两种卡背颜色的尚未公开卡牌中各随机选择一张，先翻开玩家颜色的卡牌并结算揭牌效果，再翻开对手颜色的卡牌并结算揭牌效果，然后进入作弊阶段。玩家完成操作或跳过后，电脑根据合法可见信息决策并执行，禁止操作玩家本次行动已涉及的卡牌；阶段结束后清空这份禁止列表。作弊增加的子弹落入对方的子弹区域。第四次揭牌按同样的颜色优先级翻开所有剩余暗牌并结算揭牌效果，随后直接计分，不再作弊。
4. 结算阶段，相机切至垂直桌面的计分视角，四组对位依次强调卡牌并显示累计得分。基础规则胜者得 2 分，负者得 0 分，平局双方各得 1 分。
5. 执行阶段，相机切至正对对手的射击视角，胜方举枪执行一次射击；同分时双方结果先统一判定，再同时播放双枪演出，不因一方倒下取消另一方射击。当前使用占位枪械与反馈，可配置音效资源。
6. 若双方存活，相机回到桌面，双方场上牌移入各自弃牌堆，保留手牌并移除一枚筹码；筹码为零时继续战斗。随后自动准备下一回合。任意一方生命耗尽则显示战斗结果和筹码奖励，可重新开始一场独立战斗。
