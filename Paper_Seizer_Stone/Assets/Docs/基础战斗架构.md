# 基础战斗架构与使用

## 当前范围

仅基础石头、剪刀、布的单场战斗。非基础牌、标签、卡牌变形、特殊判定、揭牌能力、衍生卡、角色道具和额外射击暂不实现。奖励选择、商店、烧牌及完整冒险流程留待后续。

已编写基础牌配置、牌组记录、战斗实例、区域流转、回合规则、电脑决策、输入与演出调度，以及使用占位物体的独立桌面场景。本轮按工作规范没有运行编译、测试或编辑器试玩；打开 Unity 后的实际运行情况仍需人工确认。

## 入口与配置

打开 `Assets/Scenes/BasicBattle.unity`，未进入 Play 时即可看到并编辑完整桌面。场景的 `BasicBattle` 对象绑定战斗配置、输入组件、桌面与相机预制体；桌面、槽位、枪械、子弹、筹码、对手、灯光、相机和 Canvas 均已保存为场景中的预制体实例，不在运行时搭建。原场景中其它对象（包括 EventSystem）保留，不需要临时 Editor 菜单。

场景使用以下三个主要预制体：

| 资源 | 编辑内容 |
| --- | --- |
| `Assets/Game/Prefabs/BattleTable.prefab` | 桌面布局、双方槽位与手牌区、牌库、枪械、子弹、筹码、对手和灯光 |
| `Assets/Game/Prefabs/BattleCameraRig.prefab` | 已保存的 Camera、AudioListener 和操作、计分、射击三个机位 |
| `Assets/Game/Prefabs/BattleHUD.prefab` | Canvas、回合与比分面板、操作提示、结算及错误面板 |

`Assets/Game/Prefabs/Props/` 内另有桌子、槽位、牌堆、左轮、子弹、筹码和对手预制体，作为桌面的嵌套实例使用。`Assets/Game/Materials/` 保存各部位可直接编辑的材质。

卡牌统一使用 `Assets/Game/Prefabs/Card.prefab`，已保存牌体、正面、卡背、半透明预览、中文文字与碰撞体。运行时只按战斗数据实例化与回收已保存的卡牌预制体；筹码超过场景预置数量时，从已保存的筹码预制体扩展对象池，不创建场景结构。

桌面 `EditorPreview` 提供编辑器中的卡牌摆放预览，进入战斗时隐藏，并使用 EditorOnly 标签排除出构建。它与运行时的卡牌实例相互独立。

`Assets/Game/Data/Cards/` 中提供三张基础卡牌资源。可以复制已有资源，再在 Inspector 编辑稳定 ID、显示名称、基础手势、图像和牌面颜色；不同资源不要共用同一 ID。当前不能通过配置获得非基础牌能力。

战斗资源配置双方的卡牌与份数、初始生命、筹码和随机种子。默认双方各有石头、剪刀、布各四张，玩家两条生命、敌人一条生命、八枚筹码。每副牌至少五张。种子为零时每场使用新种子；指定非零种子可以固定规则随机序列。

配置资源不保存战斗变化，也不在运行中修改。场景已加入 Build Settings，原 SampleScene 保留。

## 数据与代码目录

| 路径 | 职责 |
| --- | --- |
| `Assets/Game/Runtime/Core/` | 无 Unity 依赖的卡牌与战斗状态、指令、事件、规则和电脑策略 |
| `Assets/Game/Runtime/Configuration/` | ScriptableObject 配置，转为纯数据供规则层使用 |
| `Assets/Game/Runtime/Flow/` | 一批逻辑结果对应一段演出，结束后推进阶段 |
| `Assets/Game/Runtime/Input/` | 拾取、拖拽、落点、确认及取消 |
| `Assets/Game/Runtime/Presentation/` | 卡牌 View、区域布局、物体池、桌面、相机和表现 |

`CardDefinition` 是共享静态配置。`DeckCardRecord` 表示冒险中拥有的某张牌，保留记录 ID 和配置 ID；目前不包含标签。`CardRuntime` 在开战时创建，每张实体牌拥有独立实例 ID，保存原阵营颜色、配置以及本回合公开与揭牌记录。

抽牌、交换、弃置和洗牌都移动同一个实例，不复制卡牌。位置由 `BattleState` 中双方的抽牌堆、手牌、四槽和弃牌堆统一维护。View 回收只回收场景对象，不销毁 Runtime。

当前不实现战斗变形和跨阵营换牌，因此 Runtime 不提前加入对应的可变配置与效果系统。

## 操作

- 布阵：拖动手牌放入己方四槽；确认前可以换位、替换或把牌拖回手牌区。此时操作的是布局草稿，确认后才提交战斗状态。
- 确认：点击桌面「确认出牌」，或按 Enter / 空格。四槽未满时不会提交。
- 作弊换位：拖动己方场上的牌到另一己方槽位。
- 作弊换牌：手牌拖到场上牌，或场上牌拖到具体手牌。一次合法操作即消耗本次作弊机会。
- 额外抽牌：作弊阶段点击己方「牌库」，向对方增加两发子弹。
- 跳过：点击「跳过作弊」，或按 Enter / 空格。
- 取消：拖拽时按 Esc / 右键；无效落点也会回位，不增加子弹、不消耗行动。
- 拖拽过程中，合法目标会高亮；对方弹巢已满时只能跳过作弊，不能继续拖牌作弊。
- 结束：显示胜负和筹码奖励；点击「再来一局」或按 Enter / 空格开始一场新的独立战斗，初始生命恢复配置值。

界面使用提供的 `Assets/Fonts/ResourceHanRoundedCN-Bold SDF.asset`，其源字体为同目录 TTF。卡牌、桌面文字与 Canvas 均已绑定此字体，开启动态多图集以容纳中文字符。字体、字号、颜色、对齐和区域大小在各预制体的 TextMeshPro 组件中编辑，不由运行时代码覆盖。卡牌名称、桌面标签、按钮、战斗动态及操作提示均为中文。

屏幕 HUD 使用已保存的 Canvas，由 `BattleHud` 组件读取表现快照更新文字和面板显隐，不再使用 OnGUI 绘制。上方分别显示回合阶段与双方得分，下方显示战斗动态和操作说明，结束后显示居中结算面板。CanvasScaler 负责按屏幕缩放，底部提示使用布局组和 ContentSizeFitter 随文字换行调整高度；不显示开发用随机种子，也不增加装弹数字。面板和文字均不拦截桌面鼠标输入。

视觉采用深色底板、暖金色标题、蓝色我方与赤褐色对手。卡牌使用不同的浅色牌面，牌库与弃牌计数分行显示，按钮用材质区分可操作与等待状态。屏幕面板在 Canvas 的 Image 和 TextMeshPro 组件中编辑，桌面材质在 Materials 目录编辑，无须临时 Editor 菜单。

## 如何调整布局与替换美术

- 槽位：移动 `PlayerSide` / `EnemySide` 下的槽位实例；`CardAnchor` 决定卡牌最终位置和朝向，绑定数组顺序对应四组对位。
- 手牌：移动双方 `HandAnchor`；间距、展开间距、扇形角度与最大宽度在 TabletopView 配置。
- 牌库与弃牌：移动牌堆或 `DiscardAnchor`，卡牌飞入飞出的目标随定位点变化。
- 拖拽高度：移动 `DragPlane`，鼠标拖拽平面跟随其位置与朝向。
- 枪械：在 Revolver 预制体内替换模型，保留根节点和 MuzzleFlash 引用；桌面上的 `GunRestPose` 与 `GunAimPose` 决定摆放及举枪位置。
- 机位：移动相机预制体内的 `TablePose`、`ScoringPose`、`ShootingPose` 并旋转朝向；相机参数直接在 MainCamera 编辑。选中相机控制器可看到机位标记。
- 文字与界面：在 BattleHUD 的 RectTransform、Image、TextMeshPro、布局组件和 CanvasScaler 中调整；对应中文牌库与桌面文字在 BattleTable 中调整。
- 更换组件或删除节点后，需要同步维护 TabletopView、BattleCameraRig、BattleHud 和 CardView 的序列化引用；运行时不会用临时生成的物体替代缺失引用。

## 回合与信息隔离

流程为：准备与抽牌 → 布阵确认 → 揭牌 → 玩家作弊或跳过 → 电脑决策并执行，重复三次 → 第四次全部揭牌 → 四组计分 → 射击 → 下一回合或结束。

首回合双方各抽五张，后续保留手牌再补四张；抽牌堆耗尽后仅将弃牌堆洗入。每回合双方子弹重置为二，公开状态和本回合揭牌记录重置。场上明牌换位或与手牌交换时保持原公开状态。

每次按最初卡背颜色处理，玩家颜色先于电脑颜色。前三次每种颜色随机揭示场上一张暗牌，第四次揭示全部剩余暗牌。

玩家操作结束后，电脑才接收新的 `BattleObservation`。这个独立快照不包含 Runtime 引用、暗牌配置、抽牌顺序或暗牌手势；只包含电脑自己的牌和玩家公开的牌。玩家行动涉及的卡牌 ID 加入当次禁止操作列表，电脑行动结束清空。

电脑初始布局随机；作弊时比较可见信息下换位或换牌带来的分差收益，未知牌按中性期望处理，偶尔选择额外抽牌。它不是读取玩家暗牌的全知策略。

己方暗牌的半透明预览由玩家视角快照生成，不改变规则中的公开状态。对手暗牌只显示卡背。之前公开的牌换回手牌后，本回合仍保留公开状态；电脑目前不实现跨回合记牌策略。

## 结算与表现

每个指令先检查合法性，再原子修改状态，产生有序的 `BattleEvent` 列表。每个事件附带当时的玩家视角快照，View 按顺序显示，避免直接读取最终 Runtime 导致提前显示未来结果。

表现层负责位置、牌面、半透明预览、翻牌、计分强调、实体子弹与筹码。物体池管理手牌和场上 View，抽牌堆、弃牌堆使用已保存的占位模型和计数表示。单卡、命中与空枪音效在 TabletopView 配置，AudioSource 已保存在桌面预制体中，默认没有外部音效素材。

相机只有操作桌面、垂直计分、射击三个定位点，不设独立对手特写。演出期间关闭操作输入；相机和布局动画使用已安装的 DOTween。运行时移动已保存的相机，不创建相机或重设其编辑器参数。

平局先抽取双方射击结果，再统一扣生命，并同时播放枪械反馈。双方同时死亡按玩家失败处理。筹码只影响奖励，扣至零后继续战斗。

卡牌预制体必须完整绑定 Visual、Face、Ghost、FaceText、GhostText、Back、碰撞体以及双方卡背材质，不再提供自动构建外观的分支。替换美术时保留或重新绑定这些引用，碰撞体尺寸直接在预制体编辑。牌面动态颜色和图片通过 MaterialPropertyBlock 应用，不修改共享材质资源。

卡牌预制体根节点已配置 BoxCollider，CardView 同时声明组件依赖并在初始化时显式检查引用。Unity 组件使用 `== null` 判断缺失，不使用 `??`；输入、相机和桌面组件在场景中显式绑定，不在运行时补建组件。

## 后续冒险接入

`BattleController.BattleFinished` 提供玩家视角结算快照，其中包含胜负、剩余生命与筹码奖励。后续冒险管理器可以用它更新冒险记录，并把保存的牌组与剩余生命传给下一场 `BattleEngine`；不要将桌面模型或 ScriptableObject 当作存档。

本入口中的「再来一局」只用于重新开始独立战斗，不代表进入下一场冒险战斗。
