# 基础战斗、商店与冒险循环

## 当前范围

基础牌与八张特殊商品牌的连续战斗、炼金玻璃瓶战斗内变形、特殊对位判定、揭牌与获胜能力，以及商店购买、摊牌烧牌和进入下一场战斗。床单、论外牌（枪／虚无）、标签、角色道具和额外射击暂不实现。

已编写基础牌、牌组、敌人和商店配置，以及冒险数据、单场规则、电脑决策、输入和演出调度。冒险数据在本次运行内维护。本轮按工作规范没有运行编译、测试或编辑器试玩。

## 入口与配置

打开 `Assets/Scenes/BasicBattle.unity`，未进入 Play 时即可看到并编辑完整桌面和虚拟投影房间。场景的 `BasicBattle` 对象绑定战斗配置、输入组件、桌面与相机预制体；桌面、槽位、枪械、子弹、筹码、对手、灯光、相机、Canvas 和房间均已保存为场景中的预制体实例，不在运行时搭建。房间使用 `VirtualProjectionRoom`，将原有 `Virtual Projection` 图片平面替换为地板、后墙、左右墙和顶面组成的可编辑模型。原场景中其它对象（包括 EventSystem）保留，不需要临时 Editor 菜单。

场景使用以下主要预制体：

| 资源 | 编辑内容 |
| --- | --- |
| `Assets/Game/Prefabs/BattleTable.prefab` | 桌面布局、双方槽位与手牌区、牌库、枪械、子弹、筹码、对手和灯光 |
| `Assets/Game/Prefabs/BattleCameraRig.prefab` | 已保存的 Camera、AudioListener 与相机配置 SO 引用 |
| `Assets/Game/Prefabs/BattleHUD.prefab` | Canvas、回合与比分面板、操作提示、结算及错误面板 |

| `Assets/Game/Prefabs/Shop/ShopTable.prefab` | 商店 Panel：商品、价格、实体钱包、持有牌预览、分页列表、烧牌入口、下一战按钮 |
| `Assets/Game/Prefabs/Panels/BurnTable.prefab` | 烧牌 Panel：摊牌范围、卡牌容器、火盆、实体钱包、选择信息、确认与返回按钮 |

商店与烧牌实例在编辑状态默认关闭，可打开各自预制体独立编辑；进入 Play 后控制器初始化实例，各自的 TablePanel 管理内容显隐及转场。BattleTable 也配置 TablePanel，场景显式连接独立 BattleHUD 的转场组件。商店屏幕 UI 在原位淡入淡出，战斗与烧牌 HUD 保留原有移动转场。桌体、灯光、相机和投影房间共用，战斗、商店、烧牌三种布局轮流飞入飞出；房间不参与 Panel 转场。

`TableFlyGroup.parts` 仅保留实际参与转场的有效引用；删除物件后应同时移除数组中的空条目。BattleTable 预制体已清理四个空条目，BasicBattle 场景单独绑定的转场物件追加在数组末尾；调整预制体数组顺序或长度时，需同步维护场景的数组覆盖，避免覆盖其它物件或重新产生空槽。

`Assets/Game/Prefabs/Props/` 内另有桌子、槽位、牌堆、左轮、子弹、筹码和对手预制体，作为桌面的嵌套实例使用。当前三渲二材质副本保存在 `Assets/Game/art/matrial/Toon/`，原始材质继续保留在 `Assets/Game/Materials/`；房间材质位于 `Assets/Game/art/matrial/shader/VirtualProjection.mat`。

卡牌统一使用 `Assets/Game/Prefabs/Props/Card_RoundedPreview.prefab`，名称沿用最初样品名，现已接入战斗、商店与烧牌流程。原 `Assets/Game/Prefabs/Card.prefab` 仍保留为旧样式资源。运行时按战斗数据实例化与回收已保存的卡牌、子弹和筹码预制体。子弹与筹码优先复用桌面中保存的物理实体，不足时从相应预制体扩展对象池，不创建场景结构。

卡牌根节点的 CardView 中，`faceText` 绑定 `Visual/FaceTitle` 的 TMP 文字，`back` 绑定 `Visual/Back` 的 MeshRenderer；这些初始化引用继续保留，不能只删除对象而保留空引用。圆角牌的 Back 使用 `Card_Rounded_Back.mat`，共用黑金色 `back_2d`，通过美术 SO 中的蓝／红卡背乘色区分原阵营；旧卡牌的 PlayerBack_Toon／EnemyBack_Toon 资源不变。

桌面 `EditorPreview` 提供编辑器中的卡牌摆放预览，进入战斗时隐藏，并使用 EditorOnly 标签排除出构建。它与运行时的卡牌实例相互独立。

## 圆角卡牌与浅凹承托槽位

`BattleTable/EditorPreview/Preview_3` 是桌面中的嵌套预览实例，并非单独的预制体文件。独立卡牌资源为 `Assets/Game/Prefabs/Props/Card_RoundedPreview.prefab`；场景的 `BattleController.cardPrefab`、烧牌的 `BurnTableView.cardPrefab`、商店中的已保存卡牌实例与编辑预览均已接入该资源。可在 Unity 中双击卡牌进入 Prefab 模式，旋转视角查看正面、背面和薄纸边。

样品为宽 `0.74`、长 `1.11`、厚 `0.03` 的实体圆角卡牌，圆角半径约 `0.05`，使用 `Assets/Game/art/model/Cards/Card_Rounded_Body.obj` 与 `Card_Rounded_Front.obj`。模型有真实圆角和窄倒角，不依靠方形 Cube 叠加裁角透明材质。前后面按约 `2:3` 比例显示原画，正面先选 `scissor_2d.png`，背面选 `back_2d.png`；其它 `Assets/Game/art/texture/card/` 图片均可作为正面替换图。原有图片和导入设置保留。

CardView、碰撞体以及 visual、face、back、双方卡背材质和文字／私人预览等引用均保留。新增序列化开关 `textureOnly`，圆角牌开启，旧牌默认关闭。圆角牌使用单张实体表现：已有完整图案的牌不叠加 TMP 和半透明私人预览；玩家自己已知的场上牌直接显示正面，对方未揭牌仍显示卡背。该处理只决定本地外观，不改变 `Revealed`、规则观察信息或电脑决策。

正反面材质位于 `Assets/Game/art/matrial/shader/Cards/`，分别是 `Card_Rounded_Front.mat` 和 `Card_Rounded_Back.mat`，共用 `Card_PaperSurface.shadergraph`。`_BaseMap`、`_BaseColor` 保留 Main Texture／Main Color 标记，兼容已有 CardView 换图、改色接口；节点图采用轻微受光和较高的保底亮度，纸边为浅暖纸色。`_ArtworkStrength` 默认 `1`；CardView 根据是否有图片写入 `1`／`0`，缺图时覆盖为白图并启用文字，避免沿用对象池中上一张牌的图片。

卡面图片是名称与说明的依据。`Assets/Game/Data/Cards/` 的十二份规则 SO 均已关联 `Assets/Game/art/card/` 中的美术 SO，牌组、商店与变形引用的 GUID 和稳定 ID 保留。十一种可售牌都已配图；碎玻璃暂无独立素材，使用白色牌面、名称与说明回退。三叉戟和绸缎的规则已随卡面改为揭牌登记、回合落后时扣对方三分，旧抽牌和奖池加筹码效果移除。

### 卡牌美术配置

打开 `Tools > 卡牌美术配置`，选择已有卡面或点击窗口内的「新建美术配置」，编辑名称、说明、正面图片、图片是否自带文字、牌面乘色、卡背图片和双方卡背乘色。新建资源自动存入 `Assets/Game/art/card/`；直接选择 SO 也可通过 Inspector 编辑并查看图片。菜单只保留工具窗口入口。

选择「对应规则 SO」后点击「关联到规则 SO 并保存」，将美术配置写入 CardDefinition.appearance，支持撤销。已关联时，显示名称、说明、图片、牌面颜色均优先读取美术 SO；规则 SO 的旧显示字段仅用于未关联资源的兼容回退。稳定 ID、手势、能力和变形目标仍由规则 SO 管理。

在 Prefab 模式或场景中选择卡牌根节点，设置 CardView 的 `previewAppearance`、`previewSide`、`previewFaceDown`，可预览正反面及原阵营颜色；也可通过窗口的「应用到选定的预览卡牌」指定 SO。默认绑定剪刀。编辑时使用属性块更新外观，运行时正面由真实卡牌定义覆盖；统一卡背样式取自预制体的预览 SO，不从未知卡牌身份读取。完整卡图默认不叠加 TMP，缺图或关闭 `artworkIncludesText` 时显示文字。

`CardDefinition` 是共享静态配置。`DeckCardRecord` 表示冒险中拥有的某张牌，保留记录 ID 和配置 ID；目前不包含标签。`CardRuntime` 在开战时创建，每张实体牌拥有独立实例 ID，保存原阵营颜色、配置以及本回合公开与揭牌记录。

抽牌、交换、弃置和洗牌都移动同一个实例，不复制卡牌。位置由 `BattleState` 中双方的抽牌堆、手牌、四槽和弃牌堆统一维护。View 回收只回收场景对象，不销毁 Runtime。

CardSpec 是只读规则数据，包含手势、能力与变形目标 ID。CardRuntime.Definition 允许规则层在炼金玻璃瓶交换后替换为碎玻璃，实例 ID、来源记录、原阵营、明暗状态和揭牌记录不变；跨回合保留变形，战后不回写 AdventureState 的持有记录。下场战斗从原始炼金玻璃瓶配置重建。跨阵营换牌仍暂不实现。

ObservedCard 只在可见时携带只读 CardSpec；暗牌的配置、手势和能力均为空。电脑的开始快照持有原只读数据，不因后续 Runtime 变形而改变。CardRules 同时供规则层和电脑的合法可见评估使用，电脑也会预计交换炼金玻璃瓶后的剪刀类结果。

## 操作

- 布阵：拖动手牌放入己方四槽；确认前可以换位、替换或把牌拖回手牌区。此时操作的是布局草稿，确认后才提交战斗状态。
- 确认：点击桌面「确认出牌」，或按 Enter / 空格。四槽未满时不会提交。
- 作弊换位：拖动己方场上的牌到另一己方槽位。
- 作弊换牌：手牌拖到场上牌，或场上牌拖到具体手牌。一次合法操作即消耗本次作弊机会。
- 额外抽牌：作弊阶段点击己方「牌库」，向对方增加两发子弹。
- 跳过：点击「跳过作弊」，或按 Enter / 空格。
- 取消：拖拽时按 Esc / 右键；无效落点也会回位，不增加子弹、不消耗行动。
- 拖拽过程中，合法目标会高亮；对方弹巢已满时只能跳过作弊，不能继续拖牌作弊。
- 胜利：短暂停顿后自动清走战斗组件，进入商店。
- 商店购买：点击桌面商品卡，支付标价后将一张新牌加入持有牌组；该商品售罄。
- 商店烧牌：点击「烧牌整备」切换桌面，展开整个持有牌组；点击实体牌查看能力并高亮，确认后支付三筹码并烧掉这一张，至少保留五张。完成后返回原商店；Esc／返回按钮可以取消。右侧分页列表保留为牌面预览。
- 下一战：点击「下一场战斗」，保留剩余生命、钱包余额及调整后的牌组，按敌人顺序进入下一场。
- 失败：显示本次冒险抵达的场次；点击桌面「重新开始」或按 Enter / 空格，从初始配置开始新的冒险。

界面使用提供的 `Assets/Fonts/ResourceHanRoundedCN-Bold SDF.asset`，其源字体为同目录 TTF。卡牌、桌面文字与 Canvas 均已绑定此字体，开启动态多图集以容纳中文字符。字体、字号、颜色、对齐和区域大小在各预制体的 TextMeshPro 组件中编辑，不由运行时代码覆盖。卡牌名称、桌面标签、按钮、战斗动态及操作提示均为中文。

当前 BattleHUD 常驻界面仅保留 RoundPanel 和 Footer，其 TableFlyGroup 的 Parts 也只绑定这两个面板，不保留已删除 UI 的空槽。BattleHud 的 playerScore、enemyScore 和 instructionText 为可选文字引用；移除对应 UI 后可以留空，后续恢复显示时重新绑定即可。

桌面 `SideTableBindings` 的 DrawLabel、DiscardLabel、ScoreLabel，以及 `TabletopView` 的 roundLabel 同样为可选文字引用；未绑定时跳过对应文字更新，不阻止战斗初始化。槽位、手牌／抽牌／弃牌定位点、牌堆、枪械、子弹区与确认按钮等功能引用仍必须配置。

屏幕 HUD 使用已保存的 Canvas，由 `BattleHud` 组件读取表现快照更新文字和面板显隐，不再使用 OnGUI 绘制。上方显示场次、回合阶段、敌人名称与双方得分，下方显示战斗动态和操作说明；失败后显示居中冒险结算面板，胜利后自动转入商店。CanvasScaler 负责按屏幕缩放，底部提示使用布局组和 ContentSizeFitter 随文字换行调整高度；不显示开发用随机种子，也不增加装弹数字。战斗 HUD 不拦截桌面鼠标输入，商店按钮由独立的 GraphicRaycaster 接收操作。

视觉采用深色底板、暖金色标题、蓝色我方与赤褐色对手。卡牌使用不同的浅色牌面，牌库与弃牌计数分行显示，按钮用材质区分可操作与等待状态。屏幕面板在 Canvas 的 Image 和 TextMeshPro 组件中编辑，桌面三渲二材质在 `Assets/Game/art/matrial/Toon/` 编辑，材质节点图位于 `Assets/Game/art/shader/Toon/`，无须临时 Editor 菜单。

## 如何调整布局与替换美术

- 槽位：移动 `PlayerSide` / `EnemySide` 下的槽位实例；`CardAnchor` 决定卡牌最终位置和朝向，绑定数组顺序对应四组对位。
- 手牌：移动双方 `HandAnchor`；间距、展开间距、扇形角度与最大宽度在 TabletopView 配置。
- 牌库与弃牌：移动牌堆或 `DiscardAnchor`，卡牌飞入飞出的目标随定位点变化。牌库预制体内保存十二层略微错位、旋转的卡背，`DeckPileView` 根据剩余张数显示对应层数，最多显示十二层；数字仍表示真实张数。每层的偏移已经保存在资源中，刷新不会重新随机。
- 子弹与筹码：双方 `BulletArea` 和中央 `Chips` 节点各绑定 `PhysicsTokenArea`。`DropPoint` 决定投放高度，`spawnSpread`、`dropInterval`、`settleTime` 和 `tumbleSpeed` 调整散布、间隔、演出等待与初始翻滚。每个区域内保存地面、四周空气墙与上盖碰撞体，修改尺寸时让落点及其散布范围保持在墙内。边界和物理实体使用 Ignore Raycast 层，避免遮挡桌面拾取。
- 拖拽高度：移动 `DragPlane`，鼠标拖拽平面跟随其位置与朝向。
- 枪械：在 Revolver 预制体内替换模型，保留根节点和 MuzzleFlash 引用；桌面上的 `GunRestPose` 与 `GunAimPose` 决定摆放及举枪位置。`TabletopView` 的举枪时长、瞄准停顿、敌方颤抖位移、角度和频率可在 Inspector 调整；只有本次需要射击的一方举枪，敌方瞄准时轻微颤抖，开枪前恢复基准姿态。
- 机位：配置统一保存在 `Assets/Game/Data/Cameras/BasicBattleCamera.asset`（`BattleCameraDefinition` SO），相机预制体的 `definition` 已绑定该资源。操作机位以更新场景的 MainCamera 初始化，计分和射击保留原有配置。三个机位均保存相对于 BattleCameraRig 根节点的位置和旋转，平滑转场时长也在 SO 中配置。打开 `Tools > 相机机位配置`，选择操作／计分／射击视角，调整绑定的 MainCamera 后点击「确认覆盖」或按单引号键，将所选机位写入并自动保存 SO，支持撤销；输入文本时快捷键不触发。请在非运行模式下配置，共用该 SO 的相机都会使用修改后的机位。旧 Transform 定位点已移除；选中相机控制器可看到 SO 机位标记。FOV 等相机参数仍直接在 MainCamera 编辑。
- 房间：在 `VirtualProjectionRoom` 根节点调整投影组件，在 `ProjectionOrigin` 调整固定参考位姿；`RoomShell` 引用保存的房间模型。具体资源位置和参数见“虚拟投影房间”小节；轻度色阶在房间材质资源中调整。
- 三渲二材质：在 `Assets/Game/art/matrial/Toon/` 的对应材质中调整三段明暗、笔触扰动和小面积高光；双击 `ToonSurface.shadergraph` 可编辑节点。效果改变模型表面的明暗与颜色，不改变模型轮廓。
- 文字与界面：在 BattleHUD 的 RectTransform、Image、TextMeshPro、布局组件和 CanvasScaler 中调整；对应中文牌库与桌面文字在 BattleTable 中调整。
- 节奏：场景 `BasicBattle` 的 BattleController 上配置 `actionPause`、`phasePause`、`victoryPause`，默认分别为 0.15、0.3、0.8 秒。动作后、阶段与机位切换后、胜利结算后分别留白；双方作弊动画仍同时进行。
- Panel 与转场：三种布局的 TablePanel 绑定世界 TableFlyGroup、HUD 转场以及需要整体显隐的 contentRoots。商店绑定 hudFade（TableFadeGroup），其余布局绑定 hud（TableFlyGroup）；存在 hudFade 时优先使用淡入淡出。世界组启用 radialWorld，tableCenter／centerOffset 指定桌心，outwardDistance、rise、randomOffset 控制外延距离、上升和随机偏移。parts 只配置具体道具或陈列包装节点；runtimeRoots 自动收集直接子级中的活动 CardView／Rigidbody，逐张牌、逐枚筹码和子弹飞离，不移动整块 ShopWorld，也不收集空气墙。不要将同一层级的父子同时加入列表。移动式 HUD 关闭 radialWorld，使用 RectTransform 锚点偏移。商店 HUD 的 TableFadeGroup 引用预制体中保存的 CanvasGroup，duration 默认 0.3 秒；仅改变透明度，保留 RectTransform 排版，过渡期间禁用交互和射线阻挡。Panel 等世界动画与淡入都结束后允许输入，交易按钮还受控制器忙碌状态约束。移动转场入场结束和离场隐藏后恢复保存姿态，避免累计漂移。
- 商店：在 ShopTable 编辑 OfferMotion 下的商品和价格、钱包空气墙、PaymentExit、OwnedDeckAnchor 与 ShopCanvas。右侧八个持有牌按钮支持分页预览，烧牌入口切至独立布局，交易期间锁定按钮和商品拾取。
- 烧牌：在 BurnTable 编辑 SpreadAnchor、spreadSize、columns、Brazier／BurnAnchor／EmberGlow、钱包空气墙与 BurnCanvas。卡牌按范围自动排成多行并随总量等比缩小，点选按独立持有记录定位。EditorPreview 提供十二张编辑预览，运行时隐藏；实际卡牌来自保存的 Card.prefab。火盆当前使用可替换的模型与发光材质，选中牌飞入后缩小消失。
- 更换组件或删除节点后，需要同步维护 TabletopView、BattleCameraRig、BattleHud 和 CardView 的序列化引用；运行时不会用临时生成的物体替代缺失引用。

## Shader Graph 三渲二材质

当前使用 Unity `2021.3.32f1c1`，配套 Shader Graph 与 URP 均为 `12.1.13`，本次没有升级项目依赖。场景的不透明道具使用可编辑的 Shader Graph 节点完成三段明暗、少量笔触扰动和小面积高光；房间另用投影节点图保留源图明暗。材质效果只改变表面颜色和光照表现，模型形状、轮廓及现有美术模型保持原样；本次没有加入描边或新的 Renderer Feature。

| 配置入口 | 调整内容 |
| --- | --- |
| `Assets/Game/art/shader/Toon/ToonSurface.shadergraph` | 通用不透明材质的完整节点图，双击可编辑中文分组内的计算节点 |
| `Assets/Game/art/shader/Toon/ToonMainLight.hlsl` | 供节点图读取 URP 主光方向、颜色和阴影的信息接口，风格计算仍在节点图中 |
| `Assets/Game/art/shader/Toon/ToonAdditionalLights.hlsl` | 读取 URP Forward 附加灯的颜色、距离／聚光角衰减、实时阴影和 Cookie，输出三段漫反射与柔化高光 |
| `Assets/Game/art/matrial/Toon/` | 各类道具的独立材质副本，可在 Inspector 修改风格参数；原 `Game/Materials` 资源保留 |
| `Assets/Game/art/shader/Toon/VirtualProjectionToon.shadergraph` | 房间专用投影、色阶与可调场景受光，沿用固定参考投影及原图明暗 |
| `Assets/Game/art/matrial/shader/VirtualProjection.mat` | 房间色阶、对比度、冷暖与场景受光；构图和图片引用仍在房间根节点组件调整 |

节点内部名称使用英文，避免当前 Shader Graph 将中文名称带入 HLSL 标识符。中文说明保留在分组标题和属性显示名中；材质属性的引用名仍沿用既有英文接口。

节点图在外部修改后，已打开的 Shader Graph 窗口需要重新载入。出现 `Graph has changed on disk` 提示时选择 `Reload`；若窗口仍保留未保存的旧数据，则选择 `Discard Changes And Reload`。也可关闭该标签页且不保存旧内容，再重新打开资源，避免旧窗口覆盖磁盘上的修复。

通用节点图保留以下七个基础分组，并增加附加灯受光计算，可从输入到输出逐段调整：

| 节点分组 | 作用 |
| --- | --- |
| `01 原材质颜色与贴图` | 保留原材质颜色和贴图输入 |
| `02 主光与接收阴影` | 取得主光方向、颜色和阴影，计算表面受光 |
| `03 低频笔触（随模型移动）` | 使用随模型移动的扰动，轻微改变明暗分界和表面颜色 |
| `04 三段明暗与柔和分界` | 混合暗部、中间调和亮部三组颜色乘数 |
| `05 材质受光与最低亮度` | 将三段明暗应用到原材质，并保留最低主光颜色 |
| `06 小面积柔和高光` | 为金属等表面添加克制的小范围高光 |
| `07 输出` | 将最终颜色交给 URP Unlit 输出；深度和法线通道由 Shader Graph 生成 |

通用材质的主要参数如下。三组明暗颜色是原贴图与 `_BaseColor` 的乘数，保留各类道具已有的颜色区分。

| 参数 | 用法与当前默认 |
| --- | --- |
| `_BaseMap`、`_BaseColor` | 沿用原材质贴图和颜色，分别标记为 Main Texture、Main Color；CardView 的 MaterialPropertyBlock 改色、换图与高亮继续生效 |
| `_ShadowColor`、`_MidColor`、`_LightColor` | 暗部、中间调和亮部的颜色乘数；木材使用偏暖灰褐，金属使用较中性的灰色 |
| `_ShadowThreshold`、`_LightThreshold`、`_BandSoftness` | 明暗分界，默认依次为 `0.33`、`0.7`、`0.035`；柔化越小，分段越明显 |
| `_BrushScale`、`_BrushStrength` | 扰动大小与强度；Scale 可调范围为 `0.1～64`，当前预设为 `14～40`；Strength 为 `0.012～0.055` |
| `_HighlightColor`、`_HighlightThreshold`、`_HighlightSoftness`、`_HighlightStrength` | 高光颜色、范围及强度；Softness 默认 `0.025`，金属和铜的 Strength 分别为 `0.12`、`0.1`，其余为 `0～0.05` |
| `_AmbientStrength` | 主光颜色的最低保底，默认 `0.35`，用于避免缺少有效主光时完全变黑 |
| `_AdditionalLightStrength` | 附加灯影响，默认 `1`、范围 `0～2`；`0` 关闭材质的附加灯贡献。通用、桌面旧木和积分器节点图共用此接口 |

通用、桌面旧木和积分器材质现在同时读取主光与场景 Point／Spot 附加灯。附加灯漫反射乘以未受主光调制的底色，再独立叠加到原结果；高光沿用各材质的高光颜色与强度，积分器还保留金属遮罩。`ToonAdditionalLights.hlsl` 提供世界位置、法线、视线、三段明暗阈值及高光阈值等八个输入，输出 Diffuse／Specular，支持 float／half；其三参数 `GetAdditionalLight` 调用接收每物体灯光列表、距离与聚光角衰减、实时阴影及 Cookie。调色、笔触、强度和表面遮罩继续在 Shader Graph 中编辑。Shader Graph 节点预览的附加灯贡献为零，场景灯光以场景内显示为准。已有前景材质参数未重置，未保存 `_AdditionalLightStrength` 的材质使用节点图默认值 `1`。

自由布光时，直接编辑场景 Point／Spot 的 Light 组件中的 Color、Intensity、Range、Spot Angle、Shadows 和 Cookie，确认 Culling Mask 包含目标对象所在层；房间所在层为 Ignore Raycast。当前支持 URP `12.1.13` Forward 的逐像素附加灯，质量管线配置保持原样：High 每物体最多 `8` 盏并支持附加灯阴影，Balanced 最多 `2` 盏且不支持附加灯阴影，Performant 关闭附加灯。四张相关节点图各使用七个 Global MultiCompile Bool：原有四个主光／软阴影关键词，加 `_ADDITIONAL_LIGHTS`、`_ADDITIONAL_LIGHT_SHADOWS`、`_LIGHT_COOKIES`，共 `128` 种图内组合；本次没有加入 Vertex 附加灯或 Light Layers 模式。

材质文件均位于 `Assets/Game/art/matrial/Toon/`，命名为 `Wood_Toon.mat`、`Felt_Toon.mat`、`Metal_Toon.mat`、`Brass_Toon.mat`、`Chip_Toon.mat`、`Opponent_Toon.mat`、`Slot_Toon.mat`、`ButtonActive_Toon.mat`、`ButtonInactive_Toon.mat`、`CardFace_Toon.mat`、`PlayerBack_Toon.mat` 和 `EnemyBack_Toon.mat`。牌面的暗部乘数较浅，笔触强度为 `0.012`，优先保留牌面图案与文字的可读性；双方牌背仍沿用蓝色和赤褐色。

## 积分器专用手绘三渲二

BasicBattle 场景的 `jifenqi/jifengqi_mesh` 使用独立材质 `Assets/Game/art/matrial/shader/ScoreCounter_Painterly.mat`，对应节点图为同目录的 `ScoreCounter_Painterly.shadergraph`。主贴图为 `Assets/Game/art/texture/f_basecolor.jpg`，底色默认白色，保留贴图本身的磨损、图案和暗色面板。选中该 Renderer 的材质槽，或直接打开材质资源，即可调整表现；双击节点图可编辑具体计算。

节点图保留九个基础中文分组：`原图与底色`、`主光阴影`、`UV短笔触`、`冷灰暗-灰褐中-暖灰亮`、`原图光影保留`、`金属与暗面板亮度mask`、`块面金属高光`、`微弱受光边缘`、`输出`。主光数据继续通过 `Assets/Game/art/shader/Toon/ToonMainLight.hlsl` 读取，附加灯通过同目录的 `ToonAdditionalLights.hlsl` 读取；材质中的 `_AdditionalLightStrength` 控制附加灯贡献，其高光仍受金属遮罩限制。风格调色与遮罩使用 Shader Graph 原生节点。

| 主要参数 | 当前预设与调整用途 |
| --- | --- |
| `Saturation`、`Exposure` | `0.94`、`1.08`，控制整体饱和度与亮度 |
| `ShadowColor`、`MidColor`、`LightColor` | `(0.68, 0.75, 0.86)`、`(0.93, 0.91, 0.89)`、`(1, 0.96, 0.88)`，分别为冷灰暗部、灰褐中间调和暖灰亮部 |
| 明暗阈值与柔化 | 暗／亮阈值为 `0.26`／`0.68`，柔化为 `0.065`，用于控制块面分界 |
| `LightingStrength` | `0.62`，降低此值可更多保留底图自带光影 |
| `AmbientStrength`、`LightColorInfluence` | `0.65`、`0.3`，控制最低受光亮度和主光颜色影响 |
| `BrushScale`、`BrushStrength`、`BrushToneStrength` | `74`、`0.025`、`0.022`，短笔触按模型 UV 固定，轻微扰动分界与颜色 |
| `HighlightStrength`、`RimStrength` | `0.075`、`0.018`，控制块面金属高光和微弱受光边缘；高光阈值为 `0.89`，柔化为 `0.035` |

高光和边缘亮部同时受到原图亮度及受光遮罩限制，减少暗色面板被整体提亮的情况。该配置只调整积分器外观，没有新增计分或交互逻辑；本次仅替换场景中目标 Renderer 的单个材质槽引用，保留 FBX 导入设置、全部 Transform、灯光、已有 `New Shader Graph` 和其它通用材质。按工作规范没有运行测试、编译、试玩或控制电脑屏幕。

## 桌面旧木材与灯光

`BattleTable/TableSurface/table` 的材质槽 0 使用独立的 `Assets/Game/art/matrial/shader/Table_Wood_Painterly.mat`，节点图为同目录的 `Table_Wood_Painterly.shadergraph`。沿用 `Assets/Game/art/texture/table_basecolor.jpg` 的 UV、板缝与磨损信息，减少细碎龟裂、橙黄色和白亮边，保留定向木纹与粗短块面笔触。当前木底色为中性灰褐：深色 `(0.22, 0.235, 0.22)`、亮色 `(0.5, 0.515, 0.46)`，灰绿仅作为少量局部风化。原 `f_table`、通用 Toon 材质、模型、UV 和全部 Transform 保留。

直接选中该材质即可调参，双击节点图可编辑原有九个中文分组及新增附加灯、贴图笔触分支。主要入口为 `DetailMip=2.2`、`DetailSoftening=0.78`（减少细裂纹）、`SourceRetention=0.08`（降低原图白边与颜色残留）、`Exposure=1.05`（整体亮度）；原图柔化与调色参数保持不变。接入独立笔触层后，程序化 `GrainStrength` 降为 `0.07`、`BrushStrength` 降为 `0.025`、`PatinaStrength` 降为 `0.1`，减少纹理与程序噪声的重复叠加。高光保持宽柔且微弱，`HighlightStrength=0.006`。

当前独立笔触层使用 `Assets/Game/art/texture/Table_Wood_Brush_ColorBlocks.png`，实际为 `1254×1254`，通过内置 image_gen 编辑初版 `Table_Wood_Brush.png` 得到，初版文件保留。新版在灰褐旧木上增加赭灰、灰蓝、灰绿和少量灰紫的大色块，增强手绘冷暖块面。原始 `table_basecolor.jpg`、材质 `_BaseMap`、模型与 UV 均保留。节点图的「贴图笔触与线框保护」分组将笔触倍率乘到已调色、未受光的木底色；「大色块冷暖」分组补入独立 RGB 色度，再沿用主光与附加灯流程，不做顶点位移或 UV 扭曲。原图未柔化采样的亮度遮罩使明暗笔触及色块在亮色线框与深色接缝处衰减，轮廓与分块位置继续由原图提供。

材质中的 `_PaintMap` 指向新版色块图，`_PaintStrength`（笔触强度，当前 `0.4`，范围 `0～1`）控制明暗叠加；`_PaintTiling`（笔触平铺密度，当前 `1`，范围 `0.1～16`）控制密度，数值越小色块与笔触越大。新增 `_PaintColorStrength`（色块冷暖强度，默认 `0.55`，范围 `0～1`）控制颜色，设为 `0` 保留明暗笔触、关闭色块冷暖；同时将两种强度设为 `0` 可关闭整个独立层。纹理顺着已有 `GrainRotation` 坐标独立采样，不经过原图的 `DetailSoftening`；亮度减去 `0.38` 后放大四倍、乘强度并限制到 `±0.3`，再经线框保护遮罩计算倍率。RGB 除以 `max(亮度,0.05)` 后限制到 `0.6～1.5`，经颜色强度和同一保护遮罩混合白色，再乘木底色；颜色位于原木材去饱和、调色之后，避免新增色块变成灰度。新图作为笔触数据导入，关闭 sRGB，使用 Repeat、NPOT None、Mip Maps、Trilinear、Aniso 8 和无压缩。完整生成提示词保存在《桌面笔触贴图提示词.txt》中。本轮未调整灯光、场景、模型、原始贴图或其它材质，未运行编译、测试或试玩。

主光配置入口是 `BattleTable/TableLight` 的 Light 组件：颜色为偏中性的暖灰 `(1, 0.98, 0.94)`，强度 `1.1`，软阴影强度 `0.7`，Bias／Normal Bias 为 `0.04`／`0.2`；方向和位置保持原样。BattleTable 内嵌积分器自带的强度 `1000` 点光已通过该实例的 Enabled 覆盖关闭，原 `jifenqi.prefab` 的灯光配置保留。

## 回合与信息隔离

流程为：准备与抽牌 → 布阵确认 → 揭牌 → 冻结作弊开始快照 → 玩家提交作弊或跳过 → 电脑基于原快照与禁止内容决策 → 双方同时播放操作，重复三次 → 第四次全部揭牌 → 四组计分 → 射击 → 下一回合或结束。

首回合玩家抽五张、对手抽四张，后续双方保留手牌再各补四张；抽牌堆耗尽后仅将弃牌堆洗入。每回合双方子弹重置为二，公开状态和本回合揭牌记录重置。场上明牌换位或与手牌交换时保持原公开状态。

每次按最初卡背颜色处理，玩家颜色先于电脑颜色。前三次每种颜色随机揭示场上一张暗牌，第四次揭示全部剩余暗牌。

每次揭牌结束、进入作弊阶段时，规则层立即保存敌方视角的 `BattleObservation`。它不包含 Runtime 引用、玩家暗牌配置、抽牌顺序或暗牌手势；只包含电脑自己的牌和玩家当时已经公开的牌。玩家提交操作后，`ObserveEnemyCheat()` 复用这份不可变快照，只补充当次禁止操作的卡牌 ID，不重新读取玩家操作后的牌位、手牌、公开牌布局或子弹变化。电脑行动结束后清空快照和禁止列表。

玩家拖拽保持实时跟手，松手确认、点击抽牌或跳过后，先在规则层依次结算双方合法行动，再由 `PresentCheats` 读取合并后的表现快照，一起启动双方换位、换牌、抽牌和加弹演出。不会依次回放玩家与电脑的中间场面，也不再保留“玩家演完后电脑才思考”的等待。

电脑初始布局随机；作弊时比较可见信息下换位或换牌带来的分差收益，未知牌按中性期望处理，偶尔选择额外抽牌。它不是读取玩家暗牌的全知策略。

己方暗牌的半透明预览由玩家视角快照生成，不改变规则中的公开状态。对手暗牌只显示卡背。之前公开的牌换回手牌后，本回合仍保留公开状态；电脑目前不实现跨回合记牌策略。

## 结算与表现

每个指令先检查合法性，再原子修改状态，产生有序的 `BattleEvent` 列表。每个事件附带当时的玩家视角快照，View 按顺序显示，避免直接读取最终 Runtime 导致提前显示未来结果。

表现层负责位置、牌面、半透明预览、翻牌、计分强调、实体子弹与筹码。物体池管理手牌和场上 View，抽牌堆使用已保存的卡背层及计数，弃牌堆使用占位模型和计数。单卡、命中与空枪音效在 TabletopView 配置，AudioSource 已保存在桌面预制体中，默认没有外部音效素材。

子弹预制体保存 Rigidbody 和胶囊碰撞体，筹码保存 Rigidbody 和凸圆柱网格碰撞体，摩擦和弹性统一在 `TokenPhysics.physicMaterial` 编辑。新增实体从对应区域上方分次投放，依靠重力自然落桌、翻滚和堆叠，空气墙防止离开区域。普通事件刷新只处理数量增减，保留已经落定的物体姿态；筹码只在战斗开始或数量实际增加时投放，每回合装弹重置时双方子弹重新投放。演出等待结束后仍继续正常物理模拟，由刚体自行休眠。物理位置、翻滚和枪身颤抖不参与胜负或弹药数量判断，视觉随机也不消耗规则随机序列。

相机 SO 保存操作桌面、计分、射击三个机位，不设独立对手特写。演出期间关闭操作输入；相机和布局动画使用已安装的 DOTween。运行时移动已保存的相机，不创建相机或重设其编辑器参数。

平局先抽取双方射击结果，再统一扣生命，并同时播放枪械反馈。双方同时死亡按玩家失败处理。筹码只影响奖励，扣至零后继续战斗。

卡牌预制体必须完整绑定 Visual、Face、Ghost、FaceText、GhostText、Back、碰撞体以及双方卡背材质，不再提供自动构建外观的分支。替换美术时保留或重新绑定这些引用，碰撞体尺寸直接在预制体编辑。牌面动态颜色和图片通过 MaterialPropertyBlock 应用，不修改共享材质资源。

卡牌预制体根节点已配置 BoxCollider，CardView 同时声明组件依赖并在初始化时显式检查引用。Unity 组件使用 `== null` 判断缺失，不使用 `??`；输入、相机和桌面组件在场景中显式绑定，不在运行时补建组件。

## 冒险与商店数据

`AdventureState` 保存玩家剩余生命、钱包、持有牌组、场次与当前商店库存。每张持有牌有独立 `RecordId`，同名牌可精确删除其中一张。购买创建新的持有记录，删除仅移除选中的记录；SO 始终是只读配置。

单场战斗结束后，胜利将剩余奖池筹码加入钱包；原有余额保留。商店默认从十一种商品抽取三件不重复商品，guaranteeSpecialCard 保证商品池存在特殊牌时至少出现一张。基础牌两筹码；锤子、刀子五筹码，柏木棒、三叉戟、绸缎四筹码，炼金玻璃瓶、花剪、火药纸三筹码。碎玻璃只用于变形，不参与出售；床单、银色左轮枪与虚无仅有美术配置。烧牌默认三筹码。商品池及价格可改，来回切换烧牌桌面不会刷新库存；可多次交易或直接离开。余额不足、售罄或触及五张牌下限时不会扣款。

交易规则先一次性完成扣款和牌组修改，再锁定输入播放演出。买入的牌飞向自己的牌组；烧掉的牌飞入火盆、旋转缩小消失。当前可见 Panel 的钱包同步移出等额筹码，避免操作隐藏商店的物理区。烧牌确认或取消后回到原有商店，按 AdventureState 同步余额和持有记录，保持售罄状态。

下一场战斗会按当前持有牌记录创建新的 CardRuntime 和战斗区域，沿用玩家剩余生命；每场奖池重新设为配置值，与钱包相互独立。敌人列表到末尾后从第一项继续。失败后结束冒险，重新开始会重置生命、牌组、钱包与场次。

`BattleController.BattleFinished` 仍提供每场战斗的玩家视角结算快照，供后续接入存档或其它冒险系统。
